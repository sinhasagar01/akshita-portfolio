Two kinds of key

An AUTHOR-EDITABLE key is a pill input — meta facts, glance grid, stat cards, the Links panel. A FIXED key is the same pill shape without the ground, because it is a label rather than a control and a box you cannot type in should not look like one. Both sit in the same place with the same type, so the row reads identically either way.

Why the unit moves into the well

"Width, px" becomes "Width" with a muted px inside the field. The label then says what the field IS and the field says what it HOLDS — and every numeric key shortens, which matters in a 320px pane.

And why the summary is the real fix

A closed group reading "Device 1 · 800px · −6° · z1" answers the question you opened it to ask. #234 already computes these — rowLabel exists at all 16 ItemRows call sites, content-derived with an ordinal fallback. The summary is not new work; it is currently thrown away.

One departure that must be recorded rather than shipped quietly

The pill is a full radius in a studio that halved every corner to 12/8/4. Full pills survive only where the shape carries meaning — the status dots, the PublishBar, the sidebar nav items. A key pill is a fourth, and its justification is that a pill reads as a KEY rather than a field, which is the entire job. Record it beside the radius scale.
