The typography contract

Source Serif 4 for display, Work Sans for body, Space Grotesk for labels. The serif keeps the optical-size mechanism Fraunces was using at opsz 144 — which is why today's headings feel considered — and drops the calligraphy. Work Sans is the closest of the candidates to DM Sans, so body text, which was never the complaint, changes least.

⚠ I have not audited the repo. Everything about the current system comes from STATE, which is a claim rather than evidence. The finding that decides the shape of the work: STATE records an unlayered h1, h2 rule setting family, weight and letter-spacing, and hazard 11 says utilities lose to it — #208 found the ink bands' font-bold was dead for exactly that. So a token swap is not a font change. And two numbers this change moves: the blog's 68ch measure is locked and pinned as a number (697.9296875px), and ch resolves against the element's font — so a family change moves it. #203's OG card arithmetic was measured against the exact Fraunces TTF and must be re-derived.

Why a third family, and why the studio wears it most

Uppercase tracked chrome is a different job from reading, and Space Grotesk's flat terminals hold at 10px where a humanist sans goes soft. The studio is mostly labels — nine dashboard pages of eyebrows, counts, metadata and field names — so this is the face it wears most, while Work Sans carries the values an author types. The serif enters the studio only as a title: the wordmark, study names, section titles and Board card titles. It never touches a form.

--font-display: "Source Serif 4", "Iowan Old Style", Charter, Georgia, serif;

--font-sans:    "Work Sans", Avenir, "Avenir Next", ui-sans-serif, system-ui, sans-serif;

--font-label:   "Space Grotesk", "Helvetica Neue", Helvetica, ui-sans-serif, sans-serif;

⚠ Not a bare serif or sans-serif. A generic fallback drops to Times or Arial, whose x-heights differ enough to reflow every box while the webfont loads — and on a site whose layout is pinned to measured numbers, a reflow is a gate failure rather than a flicker.

One system, three surfaces

Public — Source Serif display, Work Sans prose, Space Grotesk chrome. Blog — Source Serif headings, Work Sans prose at the 68ch measure. Studio — Work Sans values, Space Grotesk labels, Source Serif only for the wordmark, study names and Board card titles. No boundary rule to remember, because the body face is a sans everywhere and the serif never enters dense UI except as a title. That is the property a serif body would have cost.

What must land with it, whichever order it ships in

1 · One declaration site. The family in @theme and nowhere else, so no unlayered element rule can outrank a utility. 2 · One size per step, per the table above. 3 · Metric-matched fallbacks, never generic. 4 · The 68ch measure re-pinned. It is a locked decision held as a number, and this change moves it. 5 · The OG card arithmetic re-derived against the new display TTF.

⚠ The highest-risk consequence, stated plainly

The blog canvas measure equals the article measure, as a number — a locked decision, currently 697.9296875px, and the property the whole three-pane layout exists to protect. ch is the width of the 0 glyph in the element's own font, so changing the body family changes what 68ch resolves to. Both sides move together, so the equality should hold — but the number moves, the A1 gate pins it, and #178 established it must be proven as a NUMBER rather than as matching class strings. Re-derive and re-pin it in the same commit that changes the family, or the gate fails for the right reason and looks like the wrong one.
