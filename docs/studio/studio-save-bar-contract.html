⚠ The bar sits under the inspector, not the work area

The inspector is where the fields are, so the bar that commits them belongs under that column and nowhere else. A full-width bar claims the canvas too, and the canvas has nothing to save — it is a preview. It is a footer row matching the panes above it: the bar occupies the inspector's track and the canvas track stays empty rather than being spanned. On a single-pane page the inspector column is the page, so the same rule gives a bar the width of the content — one rule, two pane counts. And this resolves the overlap without moving the Publish pill. #248 recorded 42px of overlap on five settings panels; #258 found 18px over the case-study dock, six of them over a textarea. The pill centres over the work area, the bar occupies the inspector column, and they no longer compete for the same pixels.

⚠ The line reports state, not instruction

Today the bar carries a permanent instruction in four wordings. An instruction is read once and is noise forever after; a state is read every time. So the line becomes a dot and a phrase that changes — Saved, Saved 2 minutes ago, Unsaved changes, Saving…, Couldn't save. The instruction survives as the state's title, discoverable without being narrated. ⚠ A title is invisible on touch, so it is effectively desktop-only — acceptable for a studio, and stated rather than discovered. The failure state is why this matters most. #201 found a save silently dropped while dirty stayed true — "the state was honest the whole time, which is exactly what made it invisible." A permanent instruction cannot report a failure; this line can.

⚠ Whatever leaves the screen must land in the accessible name

"Saves every category together" is a fact about what one click does, so it moves onto the button's title and accessible name. #255 shipped exactly this defect — the unit moved out of a label, the suffix was aria-hidden, and a screen reader heard "Width" where it used to hear "Width, px". The visible label shortened and the information went nowhere; only the rendered accessible name showed it. And "Preview to see it" is about Preview, not saving — it belongs on the Preview control, not in the save bar at all.

⚠ Two surfaces that are not drift

Skills. #229 settled it — skills is a singleton(), one form holds every category, so a per-panel footer would render N bars for one document save. It is a document-level bar, a different role. It gets the same shape and its hint says what it is; it does not move. Blog. It saves on blur and has no explicit save, so its bar carries the hint and the state and no save button at all — a permanently disabled button reads as broken rather than as unnecessary, and this project deletes controls that cannot do anything. Discard stays, because discard is a real act there.
