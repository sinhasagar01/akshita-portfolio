⚠ The two controls take different treatments, and correction 20 says so

This is the most likely thing to get wrong, because both are "a row of buttons above a list". Status is a role="tablist" with aria-selected → the underline — it swaps which content is shown, and each option has its own panel of posts. View is a role="group" with aria-pressed → the accent fill — both options show the same posts, arranged differently. Same shape as Board|Editor. Two languages side by side is correct here. The roles differ, so the languages differ — do not unify them for tidiness.

⚠ Zero drafts today, and STATE already decided it

A "Drafts" tab with nothing behind it is a control that cannot do anything — the shape this project has deleted four times. STATE holds a locked decision: "Empty blog status → HIDDEN." So the status tablist is absent entirely while every post is published, and appears the moment a draft exists. Both states are drawn above. The view switcher is always present, because both its options always work.

Why cards, and what the list is for

Grid answers "which post is this" — hero-led, so the index reads like the blog it edits. It is the only arrangement where a missing hero is visible: a draft with no hero shows an empty plate rather than a word, which is an authoring fact the current page cannot show at all. List answers "what state is everything in" — denser, and it fits a dozen posts where the grid fits four. A blog grows; the list is what it grows into. Default is Grid, for the case-studies index's reason: an author arriving here is choosing which post to open.

The status word replaces the dot

A 6px dot in one of two greens is not a state anyone reads at a glance, and the meta line already spends a word on it. So the word becomes the chip and the dot goes. A draft also carries an amber left bar on its card and its row, so it reads as different even under "All". ⚠ The amber is a new colour and must be checked, not assumed. The studio's palette is cream / ink / accent plus a success green. A draft state needs its own token measured against every ground it lands on, or it is the phantom-token shape (hazard 23) in a new costume.

⚠ Every row is a grid with explicit tracks, not nested flex

The case-studies index shipped the stretching defect twice: nested flex let a control expand to fill its row, squeezing the title onto two lines and truncating the summary to one word. Adding flex: 0 0 auto at each level did not fix it, because the fragility was the structure. List row is auto 1fr auto auto — thumb, text, status, meta — one flexible track and no more. This is #178's w-0 computing to 264px: state the box, do not negotiate for it. And the gate is a rendered-width measurement, not a class-string check — a class assertion passed every broken version of that index.

The view is remembered; the filter is not

The view goes in a cookie read by the layout that already calls cookies() — #237's mechanism for the sidebar width, chosen so the first paint is correct and there is no hydration correction to animate. The status filter is not remembered. It is a transient question about the current session, and an author returning to find their posts filtered away would read it as posts missing.

The card cannot be a button element

It is clickable and it contains a status chip today and may contain controls tomorrow. Both card and row are divs with role="button" and tabindex, with an authored focus ring and authored Space/Enter — a role-button div gets neither for free, and no gate here would catch a mouse-only card.
