The canvas card's edge — four options

Each pane below is the real rig, not an impression of it: 827pt wide, holding a 1280px box scaled to 0.646, with container-x's 24px padding and the card's 28.5px margin. So the hairline renders here exactly as it renders in the studio, sub-pixel and all.

Contrast figures are card-against-the-ground-behind-it, measured in the running studio.

Now

Transparent — the card and the pane are the same colour

contrast 1.00

Nothing separates the card from the pane. The only edge is the card's own 1px @ 8% hairline, which the 0.646 scale renders at 0.646px. Look at the top corners — the card boundary is essentially not there.

Counter-scaled hairline only

contrast 1.00

The hairline is restored to a true 1px with calc(1px / var(--cs-canvas-scale)). It is crisper than A. But the ground is still identical to the card, so a 1.185-contrast line is doing all the work alone — this is the option that sounds like a fix and mostly isn't.

C

Sand ground — what the live page actually does

contrast 1.35

Puts --color-case-study-sand back behind the card, which is what the public route does and what .canvas-surface was added for. The card separates because the ground separates it, which is how it works on the real page. Hairline left scaled.

D

Cream-100 ground — separation without the warmth

contrast 1.06

A quieter ground than sand. It keeps the canvas closer to the studio's own palette rather than the case-study route's, at the cost of reading much less like the live page. Included because it is the option that most preserves the calm you were going for when you made the surface transparent.

E

Sand ground + counter-scaled hairline

contrast 1.35

C plus B. The ground does the separating and the hairline renders at its true weight instead of 0.646px, so the card's edge matches the live page on both counts rather than one.

What I would pick, and why. E. C is the fix that addresses the actual cause, because the ground was always what separated the card and the hairline was only ever a refinement on top of it. B is worth adding alongside it but not instead of it — on its own it sharpens a line nobody can see. D is a real option if you prefer the canvas to sit in the studio's palette rather than the case study's, but it trades away the one thing .canvas-surface existed to provide.

One caveat on B, stated plainly. Counter-scaling means the canvas and the public page would no longer carry the same declared value for that shadow, so it needs scoping to .canvas-static and a note in the parity rule. It does not affect layout — box-shadow never does — so the parity harness stays green either way.
