The three honest differences

1 · The rail holds one item and says so. Details is selected and cannot be deselected, and beneath it sits a stated zero rather than an empty "SECTIONS · 0" heading with nothing under it. ⚠ An empty list under a count heading is what a broken fetch looks like. The difference between "this study has no sections" and "the sections failed to load" has to be visible, or the page keeps reading as broken — which is hazard 29's whole complaint.
2 · There is no Board, so there is no toggle. The Board arranges sections; with zero sections it would be an empty grid with an Add button that cannot work, since BESPOKE_SLUGS gates the write path. A control that cannot do anything is worse than an absent one — this project has deleted that shape four times: FIT_THRESHOLD_PX, the 2xl radius, the eleven ink-700 sites, and .blog-editable.is-selected.
3 · The read-only notice moves into the rail, where the sections would be. That is where an author looks for sections, so that is where the answer belongs — not floating in the canvas, which now has a job. And a "Hand-built" chip sits in the topbar, so the study announces what it is before you go looking for what is missing.

⚠ boat-crest's hero will render at its true size, and that is the canvas being honest

Hazard 21 lists elevate-one-view, not boat-crest — but boat-crest's hero is the other open content item: still the original 2074×1058, 837KB PNG that never went through sharp, from commit 46905da. A canvas that renders the real card will render it, slowly, at its true weight. That is an argument for the re-upload rather than a bug in this PR — one studio upload re-encodes it to webp at quality 80.

What is identical, and should be

The Details inspector, the Template/Category row, the canvas card preview in both hover states, the filter row and the save bar. A bespoke study's details are edited exactly like any other study's, because they are like any other study's — only the body differs, and the body is the one thing this page correctly does not offer.

And it does not fix the parity gap

Hazard 29 also records that parity.mjs lists boat-crest among its four slugs and yields zero pairs, so a parity run over it exercises the hand-built page rather than the CMS-driven render. This PR does not change that — it makes the editor coherent, not the harness. Say so rather than letting a fixed page imply a fixed gate.
