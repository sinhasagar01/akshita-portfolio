The one real cost of three panes

Today the inspector is the full content width, roughly 1250px, so meta facts sit label beside value and every field is roomy. At 320px they stack, and six meta facts become twelve rows.

That is the price of the canvas being on screen at the same time, and it should be stated rather than discovered. Three things make it payable:

Collapsible groups, extending a pattern this editor already has — "More section fields", "Glow settings", "Sizing and position". Section, then each block, closed by default except the one you are editing.

Meta facts as compact rows, collapsing to a one-line count when closed.

The canvas does the showing. Anything you can see rendered does not need to be roomy in the form.

If after building it the pane is genuinely too tight, the answer is a wider inspector for case studies — not a return to tabs. That is a measurement to take, not a decision to make now.

Style survives 320px better than Content

Its fields are short numeric pairs, so width and rotate sit side by side at roughly 140px each, and translate X and Y likewise. Nothing here wanted the full width it had.

Style stays a toggle beside Content, not a fourth pane. They are two views of one selection rather than two selections — the same reason the blog inspector stacks Post and Body instead of tabbing them.

Closed groups carry a one-line summary so the collapsed state still tells you something. "Device 2 · 800px · z3" is more useful than a disclosure triangle with a name.
